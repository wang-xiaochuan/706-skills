# 从经历证据制作简历 · resume-from-evidence

给想整理经历、转行或改了很多版简历的人。用你自己的聊天记录发现经历，用旧简历恢复事实，再用目标岗位决定如何选材和表达。

这是 v0.1 的可复用工作流程，不是招聘成功率工具。没有聊天记录、没有目标岗位或没有现成简历，都能从已有部分开始。

## 最简单的开始方式

把 `SKILL.md` 和整个 `references/`、`assets/` 文件夹交给能读取文件的 AI 助手，或者放入所用工具支持的 Skill 目录。也可只先提供 `SKILL.md`；助手需要引用文件时再补充。各平台的自动识别和文档生成能力不同，不需要安装任何额外插件才能开始聊。

复制这段话并附上自己愿意分享的材料：

> 请读取并按 resume-from-evidence 的 SKILL.md 帮我制作简历。先阅读我提供的旧简历和工作相关聊天，提取真实经历，区分我的自述、AI 的建议与已完成成果。我想考虑【方向／还不知道】，希望避免【可选】。这里有【目标 JD／暂时没有】。每轮最多问三个关键问题，先完成一份【中文／英文】主方向内容稿，并保留可核对的经历底稿。不要编造数字，也不要把计划写成成果。

不用上传完整账号聊天历史。第一次可以只给一份简历、两三段项目对话和一份 JD。没有简历，就先讲一件做过的事：为谁解决什么问题、自己做了什么、留下什么产出。

## 你会得到什么

- 可补充的经历底稿，知道每个重要说法来自哪里。
- 目标岗位与真实经历的对照，区分写法问题和确实欠缺的经历。
- 一份主方向稿，再根据需要做少量方向版。
- 修改记录；有工具时可生成并核验 Word／PDF。

后续可以直接说：“这一版漏了我的咨询经历”“先保留正文，把履历放到第一页”“这份 JD 换了，沿用同一事实底稿再调整”。

## 文件说明

- `SKILL.md`：给 AI 的主流程。
- `references/`：证据、岗位写作、文档交付细则。
- `assets/workbook.md`：按需使用的空白工作底稿。
- `examples/fictional-case.md`：完整虚构的微型示例。
- `evals/evals.json`：三种试用情境，用于检查流程有没有编造或误归属。
- `VALIDATION.md`：本版本实际做过的检查及限制。

分享时只发送本 Skill 文件夹或压缩包。每个人的简历、聊天与工作底稿留在各自工作区。无需沿用任何其他使用者的行业、城市、资历或审美偏好。

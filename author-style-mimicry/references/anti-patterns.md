# Anti-Patterns · 失败模式与修法

风格迁移的常见失败模式与对应修法。这是一份**活文档**——每发现新的失败案例，回来追加一条。

格式约定：每条 anti-pattern 包括症状、原因、修法、示例（❌/✅）。

---

## A. 事实层失败

### A1. 信息泛化丢失
**症状**：原段"706 会客厅"在改写后变成"某个旧式客厅"或"会客厅"。

**原因**：模型在做声口迁移时，会把它认为"太具体"或"不文学"的专有名词模糊化。

**修法**：
- Phase B.1 把所有专有名词放进事实清单
- transfer-prompt.md 规则 1 末段已显式禁止
- Phase C.1 missing 字段会捕捉

**示例**：
```
❌ "我们将在某个旧式客厅举办" — 改写后丢失"706 会客厅"
✅ "我们将在 706 会客厅举办" — 专有名词原封不动
```

### A2. 数字泛化
**症状**：原段"二十几个人"在改写后变成"为数不多的人"或"几个人"。

**原因**：作家声口里数字往往不出现，模型为了像作家而省略。

**修法**：事实清单把数字明确写为一项；C.1 检查时数字必须出现在改写段（即使表述形式可以略调整）。

**示例**：
```
❌ 改写："来了寥寥几人" — "二十几"被吃掉
✅ 改写："来了二十几人" — 数字保留
```

### A3. 时间错位
**症状**：原段"先 X，然后 Y"在改写后变成"Y 之后才有 X"。

**原因**：作家声口可能偏好倒叙或非线性叙述，模型迁移时把时间顺序也迁移了。

**修法**：C.1 的 `twisted` 字段，type=temporal。

### A4. 因果倒置
**症状**：原段"因为讲得好所以人多"在改写后变成"因为人多所以讲得好"。

**原因**：模型在重组句子时丢了因果关系。

**修法**：C.1 的 `twisted` 字段，type=causal。

### A5. 幻觉细节注入
**症状**：原段没说"窗外下着雨"，改写段加了"窗外的雨敲打着玻璃"。

**原因**：模型为了让段落更"有文学画面感"，自己脑补了感官细节。

**修法**：
- transfer-prompt 规则 1 显式禁止扩展
- C.1 的 `added` 字段捕捉

**示例**：
```
❌ "窗外的雨敲打着玻璃。我开始讲" — 雨是幻觉
✅ "我开始讲" — 不在原文的细节不要加
```

## B. 声口层失败

### B1. AI 腔残留 — 强行金句化
**症状**：段尾出现"在某种意义上，这正是 X 的真谛"这种总结升华。

**原因**：模型把"风格化"等同于"哲学化"，喜欢在段尾做收束。

**修法**：
- C.2 第 5 项检测
- 给 ❌ 模式列表："不要在段尾做总结升华"
- 在档案 §四 的 ❌/✅ 里明确该作家是否会在段尾金句化（多数严肃作家是不会的）

**示例（用加缪声口）**：
```
❌ "讲完了。说到底，每一次讲座都是一次徒劳的反抗，但反抗本身已经够了。"
✅ "讲完了。"
```

### B2. AI 腔残留 — 滥用四字格
**症状**：每段都塞 2-3 个四字成语，"无穷无尽"、"千丝万缕"、"豁然开朗"。

**原因**：模型把"中文文学风"等同于"四字格密度高"。

**修法**：档案 §一 词汇语域明确该作家×译者的四字格频率。如果是低频，prompt 里强调"不要堆砌四字格"。

**示例（用赖明珠译村上春树声口）**：
```
❌ "他孑然一身，黯然神伤" — 赖明珠不这样译
✅ "他一个人，有点难过" — 更接近赖译的口语化
```

### B3. 译者漂移
**症状**：用"林少华-村上春树"档案改写，但改写段读起来像赖明珠的译本（更口语、更轻盈）。

**原因**：模型对"村上春树"的整体印象包含了多个译者，没有专门贴住某一位。

**修法**：
- 档案 §四 的 ❌/✅ 清单要写得**具体到词**
- C.2 第 2 项专门检查"用了别的译者会用的词"
- transfer-prompt 规则 3 显式说"该译者偏 {register_summary}"

### B4. 主题溢出
**症状**：用卡尔维诺风格写共居招租，结果改写段开始谈"空间作为可能世界"、"居住的几何"——这些是卡尔维诺的主题，不是用户的主题。

**原因**：模型迁移声口的同时把作家的题材也迁移过来了，覆盖了用户的实际主题。

**修法**：
- Phase B.2 主题适配判断 — 不适配时只迁句式不迁题材
- transfer-prompt 规则 4
- C.2 第 4 项专门检查

**示例**：
```
❌ "我们要让六个房间成为六种可能的居住" — 卡尔维诺式溢出
✅ "我们有六个房间，月租 X 元，看房联系 Y" — 信息保留，仅句式克制
```

### B5. 情绪漂移
**症状**：原段是中性的事实陈述，改写后带上了作家典型的情绪基调（如加缪的疏离、博尔赫斯的迷宫感）。

**原因**：作家的情绪基调藏在他的句法选择里，模型迁移句法时连带迁移了情绪。

**修法**：
- 区分"句法层"和"情绪层"——档案 §四 应该把它们分开
- 如果用户原段是中性的，prompt 里说"保持中性，不引入情绪基调"

### B6. 长度爆炸
**症状**：原段 80 字，改写后变成 250 字。

**原因**：模型在塞 §三 §四 的特征时把段落写长了。

**修法**：transfer-prompt 显式约束"长度与原段相近（±30%）"。

### B7. 长度坍缩
**症状**：原段 200 字，改写后压成 50 字。

**原因**：模型把"克制"等同于"缩短"，砍掉了原段的细节。

**修法**：同上长度约束 + Phase C.1 missing 检查（被砍的细节会被 C.1 捕捉）。

## C. 流程层失败

### C1. Critique 死循环
**症状**：C.2 重写一次，分数从 6 升到 7，再重写又掉回 6，反复横跳。

**原因**：每轮重写引入新问题，新问题被下一轮 critique 抓住，又重写又出新问题。

**修法**：硬上限 2 轮自动重写。第二轮没收敛就升级用户。

### C2. C.2 通过但 C.1 失败
**症状**：C.2 重写后声口贴近度 9/10，但事实丢失了。

**原因**：C.2 的 rewrite 没有强约束保留事实。

**修法**：
- C.2 重写 prompt 里加"不能改动事实"
- C.2 重写后**必须再跑 C.1**
- 如果 C.2 重写持续导致 C.1 失败，升级用户

### C3. 信息段被迁移
**症状**：活动通知"5 月 10 日 19 点 706 会客厅" 被改成 "在五月一个寻常的夜晚，我们将相聚在那个熟悉的房间"。

**原因**：Phase B.1 段落分类把信息段错判成了叙事段。

**修法**：
- Phase B.1 分类时明确：含日期 / 时间 / 地点 / 价格 / URL / 二维码 的段落 → 一律 cta 或 info 类
- info 类段落不进入改写流程

### C4. 主题适配判断被跳过
**症状**：用博尔赫斯档案直接改写共居招租，没有触发 Phase B.2 对话。

**原因**：模型懒得做适配判断，直接进入改写。

**修法**：
- SKILL.md 把 B.2 写为强制步骤
- 在改写前先输出"主题适配判断结果"，如果是不适配，等用户回复再继续

## D. 档案层失败

### D1. 档案样本来源混淆
**症状**：用户给的"林少华译本样本"实际上是其他译者的译文。

**原因**：用户复制时弄错版本，或网上抓的版本有错。

**修法**：
- Phase A.2 明确要求"从纸书或正版电子书复制"
- Phase A.3 抽取时做内部一致性检查——如果某段语域显著偏离其他段，提醒用户

### D2. 档案抽取过度泛化
**症状**：档案 §三 写"作家关注现代性"——这是作家全集词条级别的泛化，没有可操作性。

**原因**：模型把抽风格档案做成了写作家小传。

**修法**：
- profile-schema.md 的"反例"章节已强调
- §三 §四 每条特征要可验证（"用 X 句式"、"不用 Y 词类"）

### D3. §四 译者层留空
**症状**：档案 §四 写"译笔流畅，文字优美"——等于没写。

**原因**：用户/模型对该译者没做过比较性研究。

**修法**：
- 没把握时老实写"对该译者的比较性了解有限"
- 没有 §四 的差异化的档案 = 无效档案，不要硬上

## E. 公开发布层失败

### E1. Originality 假阳性（成语）
**症状**：originality_check 报告"归根结底"在原文和样本都出现 → 标记为重合。

**原因**：常见 4-字成语会自然重合，不是抄袭。

**修法**：
- originality_check.py 的 STOPWORDS_4GRAM 白名单
- 阈值 ≥ 7 字（大多数成语 ≤ 4 字）

### E2. Originality 假阴性（语序变化）
**症状**：改写段抄了样本里"在城市的某个角落"，改成"于某个城市角落"——n-gram 检测不到。

**原因**：n-gram 是 surface 匹配，对语序敏感。

**修法**：
- 这是 n-gram 方法的固有限制
- 通过 transfer-prompt 规则 2 的前置约束 + 用户审阅兜底
- 未来可考虑加语义相似度二级检查（不在 v1 范围）

### E3. 透明度脚注被忘
**症状**：用户跳过了脚注建议直接发布，事后被读者质疑文风像 X 作家。

**原因**：Phase D.3 的脚注建议是非强制的。

**修法**：
- v1 保持非强制（尊重用户判断）
- 但在 D.3 输出时明确写："706 公开发布默认建议加上"
- 如果未来有问题再升级为默认加上+用户可选不加

## 添加新条目的格式

发现新失败模式时，按以下格式追加：

```markdown
### [类别字母][编号]. [简短描述]
**症状**：发生了什么

**原因**：为什么会发生

**修法**：
- 在哪一阶段加什么
- 引用哪个文件 / prompt 字段

**示例**：
```
❌ ...
✅ ...
```
```

类别：
- A. 事实层
- B. 声口层
- C. 流程层
- D. 档案层
- E. 公开发布层

每类编号递增。

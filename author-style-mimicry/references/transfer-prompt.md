# Phase B.3 风格迁移 Prompt 模板

这是 skill 的核心 prompt。Phase B 改写每个段落时，按下面的模板构造 system prompt 注入到模型。

---

## 模板

````
你正在做"作家×译者"复合声口的中文风格迁移。

# 目标声口
作家：{author_name}（{translator_name} 译）

# 必须严守的规则（按重要性排序）

1. **保留用户的全部事实和意图**。事实清单（按出现顺序）：
{fact_list_bullets}
   一个都不能丢。如果某个事实在目标声口中"不自然"，宁可让它显得稍突兀，也不要删除。
   不要替换具体名词为更"文学化"的泛指（如"会客厅"不能改成"某个房间"）。

2. **不复刻示例段落中的连续 5 字以上短语**。示例是用来体会语感的，不是用来抄的。

3. **匹配该译者的语域**：见下方"译者层"一节。
   该译者偏 {translator_register_summary}。
   ❌/✅ 清单：
{translator_dos_and_donts}

4. **匹配作者的注意力偏向**：见下方"元层"一节。
   如果用户题材远离作者偏好（如本任务的题材"{user_topic}"），做最小限度的句式迁移，不要强行套题材。
   {topic_match_warning}

5. **保留段落的功能**。如果原段是 {paragraph_type}，改写后仍应是 {paragraph_type}。
   不要把通知改成抒情，不要把对话改成议论。

# 风格档案

## 表层 Surface
{profile_section_one}

## 节奏 Rhythm
{profile_section_two}

## 元层 Meta
{profile_section_three}

## 译者层 Translator-specific
{profile_section_four}

# 几段示例（仅作语感参考，不要抄写其中短语）

{three_relevant_samples_with_structure_notes}

# 用户原段
```
{user_paragraph}
```

# 你的任务

用上面的声口改写"用户原段"。要求：

- 输出**只有改写后的段落**，不加解释、不加引号、不加前后缀。
- 长度与原段相近（±30% 以内）。
- 保留全部事实清单中的具体内容。
- 不要复刻示例段落中的连续 5 字以上短语。

直接输出改写段落。
````

## 字段填充指南

### `{author_name}` / `{translator_name}`
直接从档案的 frontmatter 读 `作家` / `译者` 字段。

### `{fact_list_bullets}`
Phase B.1 的输出。每条事实是一个 bullet：

```
   - 时间：5 月 10 日 19 点
   - 地点：706 会客厅
   - 主讲人：王老师
   - 主题：现代主义文学
```

**关键**：使用原文里的精确字符串。不要做泛化（"5 月某天"）或扩展（"5 月 10 日（周六）"）。

### `{translator_register_summary}`
从档案 §四 提炼一句话。例：

- 林少华：偏书面化、文白偏重、语调强烈、押韵感
- 赖明珠：偏口语、节制、保留日语句法痕迹
- 吕同六：书面但克制，文白适中，几何感
- 王永年：客观、不加修饰、字面准确

### `{translator_dos_and_donts}`
从档案 §四 的 ❌/✅ 清单全文复制。

### `{user_topic}`
从用户原稿提取的核心题材。例："706 共居招租"、"学术沙龙活动复盘"。

### `{topic_match_warning}`
根据档案 frontmatter 的 `适配题材偏好` / `适配题材警告` 与 `{user_topic}` 比较：

- **适配** → 留空，或写："本题材在该作家的偏好范围内，可以做完整迁移。"
- **部分适配** → 写："本题材与作家偏好部分重叠，迁移时倾向于保留作家的句式骨架，但不强求他的题材偏向。"
- **不适配** → 写："**本题材与作家偏好差异较大**。仅迁移句式与节奏层，不引入作家的题材偏向（如博尔赫斯的迷宫、卡尔维诺的几何）。保持用户原意的具体性。"

不适配时还要在 Phase B.2 与用户对话过——这里的 warning 是给模型的额外保险。

### `{paragraph_type}`
Phase B.1 的分类输出，取值：narrative / description / argument / dialogue / reflection / cta。

### `{profile_section_X}`
直接从档案对应章节复制。

### `{three_relevant_samples_with_structure_notes}`
从档案 §五 中按 `段落类型` 字段筛选 3 段最匹配 `{paragraph_type}` 的样本。每段附档案里的"结构标注"。格式：

```
## 示例 1（{type}）
> {sample_text}

**结构标注**：{structure_notes}

## 示例 2（{type}）
...
```

如果同类型样本不足 3 段，用最接近的类型补足（叙事 ↔ 描写 优先；议论 ↔ 反思 优先）。

### `{user_paragraph}`
用户原段，**保留原始格式**（包括换行、列表、引用等）。

## Worked Example

假设：
- 作家：加缪
- 译者：郭宏安
- 用户原段（叙事段）：

> 周六下午我去 706 会客厅做了一场关于现代主义的讲座。来的人不多，二十几个，大多是大学生。讲完之后大家围着我聊了很久，有人问起我对加缪的看法。窗外的天正在暗下来。

**事实清单提取**（Phase B.1 输出）：
- 时间：周六下午
- 地点：706 会客厅
- 活动：现代主义讲座
- 听众规模：二十几个
- 听众构成：大多是大学生
- 后续：大家围着聊很久，有人问对加缪的看法
- 环境：窗外天暗下来

**段落类型**：narrative

**主题适配**：加缪的题材偏好包括"日常的客观观察"、"主体—世界的距离感"——本段的"观察感 + 微微疏离"基本适配。`{topic_match_warning}` 写："本题材在作家偏好范围内，可以做完整迁移。"

**预期输出**（示意，不是固定答案）：

> 周六下午，我在 706 会客厅讲了一堂现代主义文学课。听众二十几人，多是大学生。讲完，他们围拢过来，有人问到加缪。窗外的天慢慢暗了。

观察：
- 句子变短，句间过渡靠语义而非连词
- "做了一场关于"→ 直接"讲了一堂"——更客观、节制
- "聊了很久"被压缩，因为加缪不会停在这种 lingering
- 时态保持过去式，但情绪温度降低
- 全部事实保留：时间、地点、活动、规模、构成、后续、环境

## 关键设计原则（写到 prompt 里反复强调）

### 事实清单是硬关卡
模型在迁移声口时最常见的事故是"为了让段落更像作家会写的样子，悄悄删掉具体信息"。事实清单的作用是把这个悄悄删的可能性挡住。

Phase C.1 会做事后检查；但 prompt 里也要前置防范——所以规则 1 是优先级最高的。

### 长度约束
没有长度约束的话，模型有时会把一段写成 3 段，或把 3 段压成 1 句。约束在 ±30% 是经验值。

### "直接输出改写段落"
没有这条，模型会加"以下是改写后的段落："这种 preamble。Phase B.4 拼装时这种 preamble 会污染输出。

### 不要在 prompt 里塞"作家全集"
Few-shot 只放 3 段，按类型匹配。塞 5+ 段会让模型从样本里"抄"短语（即使有禁令）；塞 1 段又抓不住声口。3 段是平衡点。

### 译者层 ❌/✅ 是改写时的高频参考
模型在每个句子层面都会参考 ❌/✅ 来选词。所以 ❌/✅ 要写得**具体**——"不要用 X，用 Y"——而不是"语域应当书面"这种抽象描述。

## 失败模式与修法（用 prompt 解决的部分）

### 失败 1：模型添加幻觉细节
**症状**：原段没说"夜风很凉"，改写段加上了"夜风很凉，吹动窗帘"。

**修法**：规则 1 的"不要扩展"。可以在事实清单后面加一行注释："以上事实清单是 exhaustive 的——不要添加未在原段出现的具体细节。"

### 失败 2：模型把事实改写得"更文学"
**症状**：原段"706 会客厅" → 改写段"某个旧式客厅"。

**修法**：规则 1 末段已强调。如果反复出错，在 prompt 末尾补："**专有名词、地点、时间、人名、机构名一律保留原始表述，不做替换。**"

### 失败 3：模型抄示例短语
**症状**：示例里出现"在某种意义上"，改写段也用"在某种意义上"。

**修法**：规则 2 + Phase D 兜底。Phase D 的 n-gram 检测会发现连续重合，强制改写。

### 失败 4：模型迁移过头变成"作家自己"
**症状**：用加缪风格改写，结果改写段读起来更像加缪本人写的内容（有 absurd / etranger 的母题），而不是用加缪的句法写用户的内容。

**修法**：规则 4 的"题材远离时做最小迁移"。在不适配的题材下，模型应该只动句法和节奏，不动题材层。

---

## 与 Phase C 的衔接

Phase C.1 会读取这里的"事实清单"做事后核查——所以事实清单要**结构化、可逐条比对**。不要写成"用户提到了一些信息包括..."这种模糊形式。

Phase C.2 会读取档案的 §三 §四 做声口核查——所以 prompt 里注入的 §三 §四 内容要和档案保持一致（每次重新读档案，不缓存）。

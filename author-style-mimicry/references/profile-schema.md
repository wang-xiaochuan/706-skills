# 风格档案 Schema

每个风格档案是一份独立的 markdown 文件，存放在 706-skills vault 的 `style-profiles/` 目录下，文件名固定为 `[作家中文名]-[译者中文名].md`。

档案在两个时刻被使用：
- **Phase A** 由本 skill 抽取并写入
- **Phase B.0** 由本 skill 读出，作为 system prompt 的一部分注入

档案是"活文档"——§六（已知失败模式）和 §七（维护记录）会随使用累积更新。

---

## Frontmatter 字段定义

```yaml
---
作家: 卡尔维诺                      # 中文常用译名
作家原名: Italo Calvino             # 原文姓名（拉丁拼写或原语种）
作家国籍: 意大利                     # 文学背景判断用
译者: 吕同六                         # 中文译者姓名（必填，没有就不能建档）
代表译作:                           # 用于定位"这个译者翻的哪些作品"
  - 《看不见的城市》
  - 《如果在冬夜，一个旅人》
建档日期: YYYY-MM-DD
档案版本: 1                         # 每次修订递增
样本段落数: N                        # §五 的实际段落数
样本时期: ...                       # 译者的哪一时期（早/中/晚），可选
样本规模: small | medium | large    # small: ≤3 段; medium: 4-5; large: 6+
适配题材偏好:                       # 该作家擅长的题材，可用于风格迁移
  - 城市观察
  - 哲学短篇
  - 元小说
适配题材警告:                       # 强行套用会出违和感的题材
  - 实用通知
  - 当代社群事务
适配度建议: 用于引言/独白/沉思段，不用于实操信息段
---
```

**强制字段**：作家、作家原名、译者、代表译作、建档日期、样本规模、适配题材偏好、适配题材警告。

**前两条不达标就不能建档**：
- 译者必须明确（没有"佚名"或"未知"）
- 至少 3 段样本（少于 3 段写"档案质量受限"在档案开头警告）

## 正文章节（按顺序）

### 标题与一句话定位

```markdown
# [作家]-[译者] 风格档案

> 一句话定位：[20-40 字的精炼声口画像]
```

例：
> 一句话定位：节制、晶体般的句子，关注城市与可能性的几何，吕同六译本偏书面但不文白。

### §一 表层 Surface

#### 句长分布
- 短句（≤10 字）：约 X%
- 中句（11–25 字）：约 Y%
- 长句（>25 字）：约 Z%
- 段尾常见 [短句 / 长句] 收束

百分比是估算，不要伪精确。如果只有 3 段样本，写"约"。

#### 句式偏好
- 列出 3-5 条该作家的句式特征
- 每条要可验证（"用 X 句式"，而不是"句式有美感"）

#### 词汇语域
- 书面 / 口语 / 文白混合
- 四字格频率（高 / 中 / 低 / 几乎不用）
- 偏爱的词汇类型（抽象 / 具象 / 学术 / 民俗 / 等）
- 几乎不用的词类型

#### 标点偏好
- 哪些标点高于平均频率
- 哪些标点几乎不用

#### 修辞偏好
- 列出 3-5 种典型修辞类型
- 几乎不用的修辞

### §二 节奏 Rhythm

#### 段落长度
- 典型 X-Y 字
- 是否有独立成段的短句
- 极长段（>250 字）的频率

#### 段内"加速—减速"曲线
- 起句节奏
- 中段节奏
- 末句节奏
- 这条最难抽——观察 3-5 段样本归纳，不要硬套

#### 句间过渡风格
- 高频连接词
- 转折是用连词标记还是靠语义/结构
- 是否有重复 / 反问 / 省略 等过渡手法

### §三 元层 Meta（最重要）

> 这是抽得好坏决定档案价值的部分。**不要从样本中胡乱归纳——只写有强证据的判断**。

#### [作家] 写什么
- 列 3-6 条该作家的题材偏好
- 越具体越好（"城市与空间的几何"比"城市"具体）

#### [作家] **不**写什么
- 列 3-6 条该作家几乎不涉足的领域
- 重要！是"作家不写什么"而不是"翻译里没出现什么"——要基于对作家的整体了解，不只是 3 段样本

#### 注意力偏向
- 关注"形式"还是"内容"？
- 关注"结构"还是"事件"？
- 在具体物上停留多久？
- 是否常做反向描写（写"不存在的"或"将不会发生的"）？

#### 主体—世界关系
- 叙述者位置：贴近 / 疏离 / 缺席 / 入侵
- "我"是否袒露？多大程度？
- 与对象的距离感

### §四 译者层 Translator-specific

> **这一节是档案的核心差异化价值**。同一作家不同译者的差别都在这里。

#### [译者] 词汇偏好
- 举 3-5 个该译者特别会用而别的译者不会用的词
- 例：吕同六 偏 "亦"、"倘若"、"诚然"、"毋宁"

#### [译者] 句式习惯
- 是否大幅拆短长句？
- 是否重排原文语序？
- 是偏静态化（"是"句、"被"句）还是偏动态化？
- 处理意识流 / 对话 / 心理描写时的偏向

#### 与原作者语域的偏移
- 比原文更书面 / 更口语 / 更文白？偏移多少？
- 译者的"个人语调"压过原作者多少？（高的译者：林少华；低的译者：王永年）

#### 迁移到 [译者] 时的 ❌/✅

```
❌ "其实", "说白了", "讲真"        # 这是更口语派的译法
✅ "其实"换成"事实上"或省略

❌ 网络化表达 ("yyds", "破防")
✅ 严守书面但不死板的中线

❌ 情感外露的形容词 ("无比", "深深地")
✅ 节制
```

至少 5 条 ❌/✅。这是 Phase B 改写时最高频用的部分。

### §五 示例段落（few-shot 用 · 不要复刻其中短语）

> Phase B.3 会从这里挑 3 段最相关的（按段落类型）作为 few-shot。

#### 示例 1 · [类型 — 叙事/描写/议论/对话]
> [此处粘贴用户提供的原文段落，约 80-200 字]

**结构标注**：[1-2 句话描述这段体现了哪些 §一/§二/§三/§四 的特征]
**段落类型**：narrative | description | argument | dialogue | reflection

#### 示例 2 · ...

#### 示例 3 · ...

每段都要标 `段落类型`，Phase B.3 会按类型匹配。

至少 3 段，最多 5-6 段（再多 prompt 会膨胀）。

### §六 已知失败模式

> 持续累积。每次发现迁移失败案例就回来追加一条。

#### 模式 1：[简短描述]
- **现象**：当 X 时，模型会 Y
- **原因**：因为 Z
- **修法**：在 Phase B.X 显式 W
- **示例**：[一段失败 + 一段修正]

初建时这一节可以为空，写一句"暂无累积，会在使用中追加"。

### §七 维护记录

| 日期 | 改动 | 原因 |
|------|------|------|
| YYYY-MM-DD | 初建 | 用户首次启用 |

## 抽取流程（Phase A.3 详解）

### 步骤 1：通读样本

读 3-5 遍。第一遍找句长，第二遍找词汇偏好，第三遍找节奏，第四遍找修辞，第五遍做"反向证据"检查（这位作家不会做的事）。

### 步骤 2：填 §一 §二（表层 + 节奏）

只用样本里的实际证据填。**估算用"约 X%"**，不要写精确小数。

### 步骤 3：填 §三（元层）

这一节**结合作家整体了解**，不只是这 3 段样本。但写出来后要回到样本里验证：每条特征至少有一段样本能体现。

### 步骤 4：填 §四（译者层）

这一节是**比较性的**——你必须知道还有别的译者，才能说"这个译者偏 X"。

如果是冷门译者你没把握做比较，就老实写："对该译者的比较性了解有限，§四 仅基于样本归纳，未做译者间对比。"

### 步骤 5：嵌入示例 + 标注类型

原文不动地粘进 §五。每段配一句结构标注 + 类型标签。

### 步骤 6：用户审阅 §三 §四

把 §三 和 §四 的内容呈给用户看，问："这两节抓得准吗？有没有重要特征我漏了，或者写得不准的？"

§三 §四 是最容易抽错的——给用户审阅一道，比让档案带着错误投入使用好。

## 反例（不要这样写档案）

### ❌ 过度概括
> "句式优美，富有诗意，是经典的现代主义风格。"

无信息量。改写为可验证的描述：
> ✅ "短句和长句交替，长句内部多用破折号引出补充说明，几乎不用感叹号。"

### ❌ 幻觉特征
样本里没有的东西不要写。比如样本里没有出现书信体，就别写"善用书信体"。

### ❌ 抄百度百科作家词条
作家词条是"该作家最有名的特征"，不一定是"该译者翻出来的特征"。要回到样本看。

### ❌ 译者层留空或写"译笔流畅"
那等于没建。译者层留空不如不建档。

## 与 frontmatter 的对应关系（机器可读字段）

Phase B.0 加载档案时会用 frontmatter 做快速决策：

- `适配题材偏好` / `适配题材警告` → Phase B.2 主题适配判断的依据
- `样本规模` → 影响 Phase B 是否给出"档案有限"警告
- `适配度建议` → 影响 Phase B 在不适配场景下的默认推荐选项

正文章节是给 LLM 在 Phase B.3 做改写时读的——所以正文要写得像给一个聪明读者看的笔记，不是给机器读的结构化数据。

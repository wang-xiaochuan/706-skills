# 出版、图片与分享包验收

## 1. 单一母稿原则

每种语言保留一个锁定 Markdown 母稿；HTML、DOCX、PDF 和分享包都从它构建。不要手工在四个格式里分别修改正文。

构建链应可以回答：

```text
source corpus -> registers -> primary draft -> audited markdown
-> translated markdown -> HTML/DOCX/PDF -> package -> ZIP
```

## 2. 正文与附录

### 正文卷

- 叙事章节、图片、caption、注释和来源说明。
- 只保留对核心机制有工作的案例。
- 附录记录不得整段复制回正文。

### 附录卷

- 与正文独立的 HTML／DOCX／可选 Markdown。
- 读者字段保持少而稳定：地点、介绍、最近公开痕迹、优先链接是常见组合。
- 城市表或总览表只放读者需要的少数列，解释重叠计数。
- 完整 CSV 母表留在研究包，不因附录压缩而删除。

附录超过正文时，优先独立成册并缩减阅读字段。

## 3. 图片登记

推荐字段：

```csv
figure_id,filename,sha256,chapter,claim_supported,visible_content,caption_primary,caption_secondary,source_url,creator,published_at,accessed_at,rights_status,internal_notes,public_notes
```

### 图片任务

- **证据图**：报纸、合同、政策、账本、网页截图。
- **空间图**：外景、内景、公共区域、私人边界。
- **行动图**：聚餐、会议、劳动、互助、冲突现场。
- **文化图**：影视剧照、文学版本、海报。
- **解释图**：机制链、价格分化、平台流程。

一张外景不能替代内景，一张 logo 不能替代项目如何共同生活。每个重点 case 至少有一个能够让读者理解其空间或行动的视觉锚点；没有合适图时不要用语义无关的图填空。

### caption 三步

1. 图中可见什么。
2. 它在本章证明或帮助理解什么。
3. 来源、作者／机构、时间和必要边界。

内部 `rights_status` 与替换建议不进入公开 caption。

## 4. HTML 验收

- `lang`、标题和 viewport 正确。
- HTML 可离线打开；选择自包含 Base64 或随包相对路径，并实际测试。
- 图片数量、顺序、alt、caption 与 Markdown 对齐。
- 标题 ID 唯一；目录锚点无断链。
- 表格、长 URL、脚注和移动端宽度不溢出。
- 不加载不可控的外部字体／脚本，除非项目明确允许。
- 打开关键页面进行真实视觉检查，不只看源码。

## 5. Word 验收

- 使用真实 Heading 1/2/3，不用加粗正文模拟标题。
- 设置 Normal、标题、caption、footnote／endnote、引用和表格样式。
- 图片真实嵌入；核对媒体数量和 drawing 数量。
- 注释引用与定义数量一致。
- 表头跨页重复；单元格不截断；避免整张大表挤在正文卷。
- 页眉页脚、页码、文档属性、语言和 alt text 正确。
- 运行无障碍检查。
- 渲染所有页面为图片，制作联系表并人工检查；不能只抽首页。

## 6. PDF 验收

- `pdfinfo` 检查页数、页面尺寸和元数据。
- 字体嵌入，无乱码。
- `pdftotext` 做文本往返，确认未丢段落。
- `pdftoppm` 或等价工具渲染全页。
- 检查空白页、孤行、表格截断、图片低清、脚注越界和页码。
- PDF 是交付物时，保留可编辑母稿与构建说明。

## 7. 双语对齐

自动检查：

- H1/H2/H3 数量与顺序。
- figure ID 和文件顺序。
- footnote/endnote 调用序列与定义序列。
- 专名、数字、日期和链接。
- 附录记录 ID 和顺序。

人工检查：

- 文化概念是否为目标读者解释。
- 语气是否在翻译中变得更肯定或更营销。
- `unknown`、自述、口述和作者推论标签是否保留。
- 英文或第二语言是否独立可读，而不是中文句法的影子。

## 8. 包类型

### 完整研究包

包含：

- 正文与附录所有目标格式。
- 图片与图片登记。
- CSV 母表、来源登记和数据字典。
- 检索协议与覆盖日志。
- 审计报告。
- README。

### 项目方阅读包

包含：

- `00-START-HERE.html` 或同等清晰说明。
- 中英正文 HTML／DOCX。
- 中英紧凑附录 HTML／DOCX。
- 独立图片文件。

不包含：内部方法、审计、CSV、旧稿、删除日志或工作备注。

## 9. README 最小内容

- 项目名称、版本、核验日期、制作主体。
- 推荐阅读入口。
- 每个文件是什么。
- 正文与附录的关系。
- 数据集不是什么，例如“不是全国普查”。
- 计数不能如何相加。
- 图片和来源在哪里。
- 审计状态。
- ZIP 哈希。

## 10. 清理与版本控制

- 先列出将删除／归档的精确文件；不以目录名猜范围。
- 优先移动到废纸篓或 archive；记录恢复路径或 manifest。
- 当前版本目录只留一个明确入口。
- 旧版本号、旧页数、旧哈希和旧 README 全局搜索。
- 研究 Harness 可以保留构建中间件；对外包不能。

## 11. ZIP 门禁

推荐：

```bash
zip -r -X -q OUTPUT.zip PACKAGE_DIR
unzip -tqq OUTPUT.zip
unzip -Z1 OUTPUT.zip | rg '(^|/)__MACOSX/|(^|/)\.DS_Store$'
shasum -a 256 OUTPUT.zip
```

第三条应无输出。另核对包内文件数量、图片数量、HTML／DOCX 数量和旧稿禁入清单。

## 12. 发布残留词扫描

根据项目扩展，至少扫描：

- “公开发布前”
- “需补授权”
- “TODO” / “TBD”
- “内部” / “仅供审核”
- “AI 生成”占位
- 旧版本号、旧页数、旧哈希
- 不应公开的绝对本地路径

不要机械删除真实的证据边界说明；只移除生产过程残留和不该对外的内部话语。
